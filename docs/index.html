The problem

After meetings, action items get agreed on verbally and then quietly evaporate — not because people don't intend to do them, but because there's no lightweight system that both extracts commitments from a meeting and checks, at the next meeting, whether they were actually done. Most tools only do the first half. This agent goes beyond summarizing: it has memory and follow-through across meetings.

How it works — two Strands tools + memory

① extract_action_items

Parses a transcript into structured items: description, owner, deadline. Runs on Meeting 1 and stores the result as persistent memory.

② check_followthrough

Compares the prior meeting's stored items against the new transcript and tags each DONE, IN_PROGRESS, or NOT_MENTIONED (at risk).

③ draft the nudge

For every at-risk item, the LLM drafts a polite, ready-to-send follow-up message to the person responsible.

Who it's for

Managers, team leads, project coordinators, and scrum masters — anyone running recurring meetings where the same group commits to work week after week. It surfaces the at-risk items before they become fire drills.

Run it yourself

git clone https://github.com/MakendranG/meeting-followthrough-agent.git
cd meeting-followthrough-agent
pip install -r requirements.txt

# Web UI (this visual app):
AWS_REGION=us-east-1 streamlit run app.py

# …or the CLI:
AWS_REGION=us-east-1 python main.py

Requires Python 3.10+ and AWS Bedrock access (Claude Sonnet 4 family).
